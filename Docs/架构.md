# 架构与接口

## 同一会话如何实现

```text
手机/电脑浏览器
    │ HTTP API
    ▼
CodexDeck src/server.mjs (Node.js)
    │ 本机 CDP Runtime.evaluate
    ▼
正在运行的 Codex Desktop 主页面
    │ electronBridge.sendMessageFromView({ type: "mcp-request" })
    ▼
Desktop 已连接的本地 app-server
```

`src/desktop-bridge.mjs` 在 Desktop 主页面执行短函数。聊天与回合经页面已有的 `electronBridge` 发给 app-server，并等待 `mcp-response`；项目列表读取 Desktop 的实时本地项目状态，创建项目调用 Desktop 的本地项目服务。网关不持有第二套会话或账号状态。Desktop 退出、页面重建时，桥接断开；后续请求重新连接。审批通过页面消息监听器捕获，并在同一连接上回传决定；可重试错误通知也经此监听器传给网页。

## 状态边界

- 项目、聊天和回合归 Desktop 管；Web 项目列表取自 Desktop 本地项目状态，聊天与回合取自同一个 app-server。`project/list` 可能包含未注册到 Desktop 侧边栏的项目，不能直接作为 Web 项目列表。
- 未发送的新聊天仅在浏览器 `sessionStorage`，ID 以 `draft-` 开头。第一条消息通过 `POST /api/threads` 依次调用 `thread/start` 和 `turn/start`，并传入所选权限模式；新聊天默认使用可写工作目录的“请求批准”。若创建成功而首条消息失败，接口返回真实聊天 ID 和 `turnError`，网页保留文字供同一聊天重试。
- 主题保存在启动器用户数据目录的 `theme.txt`；网关与控制台读写同一文件，网页和控制台的 `localStorage` 只用于首屏主题缓存。网关令牌在网页 `sessionStorage`。项目名、聊天内容和 API 凭据都不写入 CodexDeck 自有数据库。
- 模型目录与默认值来自同一 app-server 的 `model/list`、`config/read`；用户选择经 `turn/start` 的 `model`、`effort` 生效。上下文用量从该聊天会话 JSONL 最近的 `token_count` 读取；尚未产生事件时显示“—”。
- 未读 ID 来自 Desktop 页面自己的 read-state 服务；网页打开未读聊天后经同一服务标记已读。目录选择窗口通过网关 API 浏览电脑文件夹，因此手机访问时选择的仍是电脑目录。
- 同步提问从 Desktop 会话服务的待答请求恢复，并通过其原生回答方法提交；异步提问从当前回合结构化消息恢复，通过 `turn/steer` 和 `expectedTurnId` 回传原回合。选项或自填内容需用户确认后发送。前端只展示待答题，成功提交后移除卡片；同一回合追加问题时，已确认完成的题目不再展示或重复提交，其它端的已接受答案也会同步隐藏。
- 网页恢复前台时强制核对最近历史，保留旧消息并显示同步状态；旧请求会被取消，超时或失败可重试。App 外壳另发 `codexdeck-app-resume` 通知，覆盖部分 WebView 缺少可见性事件的情况。
- 长历史先读取回合摘要，再对每回合读取最近 100 条过程，最多并行读取四个回合；保留首条用户消息与最终回复，用 `itemsCursor` 标记尚未读取的更早过程。用户展开活动组、单个工具时才生成详情；详情展示限量，完整输出仍可在 Desktop 查看。提问与子任务活动共用过程分页，避免另一路重新请求完整大回合。

## HTTP 接口

所有 `/api/` 请求都受可选 Bearer 令牌保护；非 GET 请求还检查 `Origin`。默认仅监听本机。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/health` | Desktop 连接、默认目录、待审批数 |
| GET/POST | `/api/theme` | 读取或设置共享主题；POST 为 `{theme:"light"|"dark"}` |
| GET | `/api/projects` | Desktop 项目列表 |
| GET | `/api/models` | Desktop 模型目录与默认选择 |
| GET | `/api/directories?path=` | 浏览电脑磁盘或指定目录的子目录 |
| GET | `/api/unread` | Desktop 本地未读聊天 ID |
| POST | `/api/projects` | 用已有绝对目录创建 Desktop 本地项目并确认该目录的信任提示；`{name,path}` |
| GET | `/api/threads?limit=&cursor=&cwd=` | 分页聊天列表；`cwd` 是精确筛选 |
| POST | `/api/threads` | 创建真实聊天，可附首条消息或目标、模型与权限：`{cwd,text?,goal?,model,effort,permissionMode}`；设置目标失败也返回真实聊天 ID 供原地重试 |
| GET | `/api/threads/:id` | 聊天元数据、上下文用量、`goal`、`completedGoal`、`goalSupported`、`goalError` 和已捕获的 `compactions` |
| POST | `/api/threads/:id/goal` | 设置或编辑目标：`{objective,model?,effort?,permissionMode?}`；暂停或恢复：`{status:"paused"|"active"}` |
| POST | `/api/threads/:id/goal/clear` | 清除目标；网页操作前确认，保留聊天记录 |
| GET | `/api/threads/:id/permissions` | 聊天当前的沙箱与审批设置 |
| GET | `/api/threads/:id/turns?limit=&cursor=` | 分页回合摘要及最近过程；最多 5 回合，每回合含 `itemsCursor`、`itemsStartId` 与可选 `itemsError` |
| GET | `/api/threads/:id/turns/:turnId/items?cursor=` | 读取本回合更早的过程；返回时间正序的 `{items,nextCursor}`，默认 100 条，超大页自动减小 |
| POST | `/api/threads/:id/turns` | 发送消息：`{text,model,effort,permissionMode}`；权限在该回合及后续回合生效 |
| POST | `/api/threads/:id/read` | 在 Desktop 中标记聊天已读 |
| POST | `/api/threads/:id/interrupt` | 中断当前回合 |
| GET | `/api/threads/:id/questions` | 当前同步／异步提问与已接受答案；返回 `{requests:[...]}` |
| POST | `/api/threads/:id/questions/answer` | 回答原问题：`{key,answers:{题目ID:答案},skipped?:[题目ID]}`；仅异步提问允许跳过 |
| GET | `/api/approvals` | 当前连接已捕获的审批与回合重连状态 |
| POST | `/api/approvals/:key/decision` | 命令审批决定：`accept`、`decline` 或 `cancel` |

静态资源只开放固定路径，包括 `public/style.css` 与白名单中的脚本、样式，不提供任意文件浏览。网页用 `markdown-it` 的 `html: false` 渲染消息，浏览器 CSP 只允许本站脚本、样式；图片另允许 data、blob 及 HTTP(S) 来源。

聊天中的本地 Markdown 图片、`imageView` 和本地附件通过 `GET /api/images` 读取。后端只为实际返回的图片引用签发绑定文件路径的签名，并检查真实图片格式及 32MiB 大小限制；请求继续经过网关访问令牌校验。前端以当前网关的相对地址携带令牌请求二进制图片，再创建 blob 地址，因此 FRP 访问不依赖电脑的本地文件路径或 localhost 地址。工具返回的内联图片在展开对应详情后才生成。

## 安全与兼容性

CDP 能控制 Desktop 页面，必须保持 `127.0.0.1` 监听。对外开放的是网关 HTTP 端口；留空令牌时访问不经身份校验，应放在可信 VPN/私网与受保护传输后面。不要将 CDP 暴露给手机或公网。

桥接依赖 `app://-/index.html`、`electronBridge` 消息形态、Desktop 内部项目服务和 app-server 方法。升级 Desktop 后先运行只读冒烟测试，再在临时聊天中测试写操作与审批。
