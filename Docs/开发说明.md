# 开发说明

## 目录

| 文件 | 作用 |
| --- | --- |
| `src/server.mjs` | 网关启动和静态资源 |
| `src/api.mjs` | HTTP API 路由 |
| `src/http.mjs`、`src/models.mjs`、`src/directories.mjs` | 请求校验、模型选择和电脑目录枚举 |
| `src/approvals.mjs`、`src/usage.mjs` | 审批中继和上下文用量 |
| `src/thread-state.mjs`、`public/js/goals.js` | 目标快照、目标操作和上下文压缩通知；复用审批中继的单一事件消费者 |
| `src/desktop-bridge.mjs` | CDP 连接、Desktop 页面消息与未读状态桥接 |
| `public/js/` | 页面状态、侧边栏、对话、模型控件、目录选择和审批交互 |
| `public/style.css`、`public/css/` | 样式入口；基础、侧栏、对话、输入区、弹窗和响应式规则分别维护 |
| `public/assets/` | CodexDeck 黑白图标，供网页与 Windows 启动器使用 |
| `tests/` | 语法、模型参数、只读在线和独立 Electron 网页测试；审批验证脚本仅用于临时聊天 |
| `scripts/` | Desktop CDP 启动脚本 |
| `Docs/截图/` | 界面测试在本地生成的截图 |

## 在 Codex 中继续开发

把本目录作为 Codex 项目根目录打开。先执行 `npm ci`；编辑 `public/` 可刷新网页查看结果。修改服务端或桥接代码后要重启 `npm start`，因为当前没有热重载。

检查顺序：

1. `npm test`：语法与模型参数检查。
2. Desktop 以本机 CDP 模式运行，启动网关，执行 `npm run test:live`。
3. 执行 `npm run test:ui`，在独立 Electron 窗口检查网页控件、桌面和 390px 布局，并保存截图。
4. 用已授权的临时目录/聊天验证草稿首条消息、项目创建、回合状态、中断及可用审批；核对项目和聊天在 Desktop 与网页都可见。

`test-live-approval.mjs` 会短暂修改指定临时聊天的审批设置，且只接受预期的无副作用 `Get-Date` 命令；它不是默认测试项。

## 当前实现取舍

- 前端使用原生 HTML/CSS/JavaScript，避免为原型引入构建链。唯一运行依赖是本地打包的 `markdown-it`。
- 页面每 2.5 秒刷新所选聊天，每 2 秒刷新审批，每 12 秒刷新列表；它不是 token 级流式展示。
- 打开聊天和恢复前台时，并行读取元信息与最近 5 轮摘要，摘要先返回就先显示。已完成回合的过程按需读取；正在运行的最新回合自动读取过程，结束后再核对最终工具状态。`GET /api/threads/:id/turns?itemsView=summary` 不等待工具条目页。
- 离开对话底部后，右下角“上一次提问”依次跳到当前阅读位置之前的用户消息；需要更早历史时自动按摘要分页补齐，并保持阅读位置。无新回合间隙时保留已加载历史的游标，离开期间新增太多回合时先补中间缺页。
- 上下文用量从会话日志末尾按 64 KiB 分块逆向读取，找到最新有效记录即停止，文件未变化时使用缓存。
- 目标通过 `thread/goal/get` 读取，并监听更新通知。Desktop 会在目标达成后自动清除当前目标，网关因此保留完成快照；该快照仅保存在当前网关进程中，启动前或断线期间已完成且清除的目标无法只靠此接口重建。
- 压缩使用 `contextCompaction` 历史项和 `item/started`、`item/completed` 通知，在对话中单独显示。来源默认按 Desktop 解释为自动压缩；协议提供 `source:manual` 时显示手动压缩文案。断线不视为压缩成功，重连后由历史记录重新确认。
- `npm run test:goals:ui` 使用模拟 API 检查目标操作、失败重试、请求竞态和手机布局，并在本地 `Docs/截图/` 生成桌面和手机截图。Electron 界面测试应逐个运行，避免共享 GPU 缓存冲突。
- 项目聊天按 `cwd` 精确读取。将来若要覆盖子目录和多主机，应先确认 Desktop 提供的归属字段与分页规则，再调整查询方式。
- 页面只渲染文本和工具结果；图片、附件、音频等高级输入尚未接入。
