# Windows 启动器

CodexDeck 的桌面启动器是一个独立的 Electron 应用。安装版与便携版均自带网关运行环境；用户仍需在 Windows 上安装并配置 Codex Desktop。网页、网关和 Desktop 使用同一套 Desktop 会话，启动器不会另建 Codex CLI 会话。

## 从双击 exe 到打开网页

1. 双击 `CodexDeck.exe`。启动器只允许一个实例，打开约 820×580 的控制台，并在系统托盘常驻。再次双击 exe 会显示已有窗口。
2. 启动器读取用户配置，检查 Codex Desktop 的进程与本机 CDP 页面，以及网关端口。默认只检查，不自动改变 Desktop 或启动网关。
3. 点击“启动全部”：
   - Desktop 已带 CDP 运行：直接进入网关启动。
   - Desktop 未运行：通过 Windows 应用激活接口带 `--remote-debugging-port` 和 `--remote-debugging-address=127.0.0.1` 启动，并等待 CDP 页面就绪。
   - Desktop 已运行但没有 CDP：先提示保存工作。用户确认后，启动器尝试正常退出 Desktop，再带 CDP 参数启动。正常退出失败时停止操作，提示用户在 Desktop 中手动退出；不会强杀进程。
4. 网关在独立的 Electron utility process 中运行。启动器等待 HTTP 监听，并发出一次只读模型请求确认 Desktop 桥接。成功后可点击“打开聊天网页”。分发版无需单独安装 Node.js，也无需运行 `npm start`。
5. 关闭控制台窗口只会隐藏到托盘。托盘菜单可重新打开控制台、启动全部、打开网页、停止由启动器管理的网关或退出启动器。退出启动器默认保留 Desktop，不中断其中的工作。

设置里的“打开控制台时启动全部”默认关闭。开启后，下次启动会自动执行安全路径；如果运行中的 Desktop 需要重启，仍会显示确认框。安装版可设置随 Windows 登录启动，登录启动时窗口隐藏到托盘；便携版不提供该选项。

## 进程与冲突处理

启动器只负责自己创建的网关子进程。如果端口上已有 CodexDeck 网关，界面会显示“由其他进程管理”，可打开网页，但“停止网关”不可操作；如果端口属于其他服务，界面提示端口占用，不会终止对方。网关意外退出时最多自动重试三次，等待重试期间可点击“停止网关”取消重试；次数用尽后保留错误状态和日志供排查。

Desktop 临时退出后，网关可以继续监听；网页下一次请求会尝试重新连接 Desktop。启动器每 5 秒检查状态，记录 Desktop、网关和桥接状态变化。CDP 只绑定 `127.0.0.1`；网关默认也只监听本机。访问令牌可由用户自由设置或留空；对外监听且留空时，监听地址上的设备可直接调用网关，建议使用可信网络或 VPN 并设置令牌。

## 配置与日志

配置位于 Electron 的 `app.getPath('userData')/settings.json`，日志位于同目录的 `logs/YYYY-MM-DD.jsonl`。当前 Windows 构建使用 `%APPDATA%\codexdeck`。安装版和便携版使用相同的用户配置目录，移动或升级 exe 不会丢失配置。默认工作目录为当前用户的“文档”目录。

访问令牌由 Electron `safeStorage` 调用 Windows 系统加密后写入配置文件。设置页不回显令牌；留空表示保持原值，也可勾选“清除已保存的令牌”。日志不记录令牌。修改网关地址、端口、工作目录、CDP 端口或令牌时，启动器会重启自己管理的网关。修改 CDP 端口后还需要由用户确认重启 Desktop，再启动网关。

## 开发、验证与构建

在项目根目录执行：

```powershell
npm ci
npm test
npm run desktop:test
npm run desktop:test:ui
npm run desktop:test:gateway
npm run desktop:test:store
npm run desktop:start
npm run dist:win
```

`desktop:test` 是配置与端口探测的 Node 测试；`desktop:test:ui` 使用隐藏的 Electron 窗口验证页面图标、纵向滚动、状态和设置交互，并在 `desktop/screenshots/qa-launcher.png` 保存截图；`desktop:test:gateway` 在随机本机端口启动独立网关子进程，并要求当前 Desktop 已启用 CDP；`desktop:test:store` 不打开窗口，验证访问令牌的系统加密与读取。`desktop:start` 打开开发版控制台。`dist:win` 构建 NSIS 安装程序与便携版 exe，输出到 `release/`。

打包内容分为两部分：Electron 主进程、预加载脚本和控制台在应用包内；网关源码、网页资源和 Desktop 启动脚本在 `resources/gateway/`。启动器在开发环境与打包环境分别解析这些路径，不依赖当前工作目录。Windows `.ico` 由 CodexDeck 黑白图标 `public/assets/codex-logo-dark.png` 生成，托盘根据系统主题切换黑白图标。exe 包含构建时的网页资源快照；网页更新后需重新运行 `npm run dist:win` 才会进入分发文件。

## 已知兼容边界

Desktop 的 CDP 页面、`electronBridge` 和内部 app-server 接口不是稳定的公开 API。Desktop 升级后，应先运行只读冒烟测试，再验证临时聊天中的写操作。Windows Store 版 Desktop 的应用 ID 目前写在 `scripts/start-desktop-cdp.ps1` 中；如果未来安装来源或应用 ID 改变，需要更新并复测启动逻辑。正式对外分发前还应配置 Windows 代码签名。
